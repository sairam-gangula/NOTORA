# KB Learning

The curricula are organized as a sequence of small implementation lessons, not a checklist to rush through. Start with one task, explain the concepts, write the code yourself, and verify behavior before moving on.

## Learning session format

For every frontend or backend step:

1. **Goal:** define one observable result and why it matters.
2. **Concepts:** explain the relevant ideas and trace the existing code path.
3. **Your attempt:** you implement a small task. I provide questions and hints first; I will not silently take over the whole feature.
4. **Review:** inspect the change for behavior, edge cases, and maintainability.
5. **Verification:** run one focused test or app check and interpret the output.
6. **Teach-back:** you explain the flow; we record the lesson and choose the next small step.

Each curriculum marks the current baseline separately from planned lessons. We can pause between steps or spread a milestone across several days.

## Tracks

- [Frontend learning](frontend/README.md): mobile React Native plus TanStack Query and Redux Toolkit.
- [Backend learning](backend/README.md): API engineering, databases, security, reliability, architecture, and applied AI.

The target is senior-level judgment over time: understanding trade-offs, debugging across boundaries, protecting data, validating assumptions, and operating software after it ships. No single project or framework list confers seniority by itself.
